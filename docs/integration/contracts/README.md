# OpenCode connection contract provenance

## Change-review contract (WI-016)

Verified on 2026-10-25 with the same hash-checked 2.1.4 executable below. [The review snapshot](opencode-2.1.4-review.openapi.json) retains the five complete runtime path objects for VCS info, status, review base, repository diff and session-turn diff, with their transitive schema closure. [The verifier](../verify-review.ps1) structurally compares subsequent runtime slices and checks disposable Git fixtures. [Sanitized evidence](opencode-2.1.4-review-evidence.json) includes repository working/branch/committed comparisons, explicit and missing bases, non-repositories, missing sessions/turns, imported turns without snapshots, and real snapshot changes from two controlled turns and their range. The [loopback provider](../review-provider-fixture.mjs) requests writes only to a synthetic session-owned file; it does not execute a real model. Node.js and Git are verifier prerequisites, not production dependencies.

`working` compares HEAD to the working copy; `branch` compares the base merge-base to the working copy; `committed` compares the base merge-base to HEAD. Base inference can return 503 for ambiguous branch history (observed when the fixture branch was created from unnamed HEAD); creating from named `main` yields `refs/heads/main` with source `reflog`. The client resolves the inferred base and supplies that ref explicitly, or accepts an explicit user ref without saving it on the server. Refs and HEAD remain mutable between requests; this is a refreshed comparison, not an atomic repository snapshot. VCS metadata was initially empty during service initialization even for a real repository and populated later, so absence of provider/branch metadata is not treated as proof of a non-repository. A non-repository working comparison returned an empty array.

Untracked text is returned as added; the staged rename fixture is returned as separate added/deleted entries. Binary changes retain a unified-diff header and a `Binary files … differ` notice with zero line counts. The client preserves these representations rather than inventing rename identities or binary content. Turn comparisons use explicit user-message IDs; a turn spans the first prompt after idle through the next idle marker, including prompts steered while busy. The retained runtime description specifies first-to-last snapshots, an active working-copy endpoint, rejection across locations, and next-user-message boundaries when no idle markers exist. Completed snapshot turns and ranges were directly observed; busy steering, active snapshots, cross-location ranges and remote/POSIX providers remain unobserved. No-snapshot imported turns return no patches and missing turns/sessions return 404.

Response bodies are parsed before owned temporary paths are replaced. Only synthetic projects/messages are retained; authorization, server passwords and configuration/provider credentials are absent. The client uses GET requests only, checks repository response locations and session ownership, requests three context lines, rejects responses above 4 MiB, and displays at most 1,000 files and 100,000 patch characters per file with explicit limit states. Empty patches remain distinct from textual patches. Reproduction:

```powershell
docs/integration/verify-review.ps1 -ExecutablePath "$env:TEMP/ocd-wi002-cli/package/bin/opencode.exe" -OutputDirectory "$env:TEMP/opencode/wi016/probes"
```

The verifier isolates server state, credentials and temporary storage, uses owned fixture repositories only, stops its provider/server and validates its scratch path before cleanup. Review requests are checked against unchanged fixture Git status before the separate controlled task writes begin. Native verification and remaining visual/accessibility checks are recorded in WI-016.

## Filesystem contract (WI-015)

Verified on 2026-10-25 with the hash-checked 2.1.4 binary identified below. [The filesystem snapshot](opencode-2.1.4-files.openapi.json) retains the complete runtime `/api/location`, `/api/fs/list`, `/api/fs/find` and `/api/fs/read/*` path objects and their transitive schema closure. [The verifier](../verify-files.ps1) compares future runtime slices structurally before accepting them. No version migration is involved.

[Sanitized evidence](opencode-2.1.4-files-evidence.json) covers directory listing, 550-file search fixtures, Unicode/space/hash/percent path encoding, raw reads, byte ranges, empty/binary/oversized files, missing files/directories and unsatisfiable ranges. Listing returns location-relative entry paths with Windows separators; find returns slash-separated paths on this Windows runtime. Both spellings work when the entire read wildcard is percent-encoded. `fs.read` returns raw bytes with a MIME type, not JSON. Empty-file range requests return 416 with `Content-Range: bytes */0`; nonempty ranges return 206 even when the requested range encompasses the entire file. Imported structured user-file source URIs survive history retrieval; import/history schemas are already retained in the task-workflow contract. Import creates disposable fixture history without executing a provider.

Evidence bodies are parsed before sanitization; owned paths/file URIs are replaced and large listing/search arrays are reduced to counts and four-entry samples. No authorization, credentials, private files, full binary downloads or provider execution are retained. [A follow-up Windows ACL probe](opencode-2.1.4-files-access-denied-evidence.json) observed a denied read returning 206 headers before the response stream failed with zero bytes delivered. The native client displayed a safe retry state and recovered after restoring the ACL. The original probe evidence predates this follow-up. Remote/POSIX runtime behavior and symlink escape semantics remain unobserved; controlled handlers also cover access-denied presentation. The native and automated evidence and client limits are recorded in WI-015.

WI-014 adds [sanitized native reliability evidence](opencode-2.1.4-native-reliability-evidence.json) for a real read-tool rejection on the same pinned 2.1.4 binary: an explicitly completed aborted assistant message can be recorded without a new idle boundary. It also records visible streaming after fixing unfinished-history hydration that discarded live text; content-part ordinals and explicit completion preserve the live overlay until authoritative replacement. No new backend operation or version is introduced; the retained task-workflow OpenAPI remains the contract baseline. The work item records native reproduction and the guarded reconciliation regression checks.

## Retained files and derivation

- `opencode-2.1.4-connection.openapi.json` is a subset of the JSON returned by the running pinned binary's authenticated `GET /openapi.json`. Retained root fields are `openapi` and `info`; the only path is `/api/info`; schemas are `ServerInfo`, `InvalidRequestErrorEncoded`, and `UnauthorizedErrorEncoded`. These schemas have no further references. Every retained protocol field and value is unchanged, including `security: []` and schema `additionalProperties` rules. Formatting alone was changed to two-space JSON with a final newline. SHA-256 of the committed CRLF file: `8AE561011017330B7E660FBDACB911751907D03164DA72EA8B6289C05FE7B600`.
- The same subset extracted from the frozen source OpenAPI compared equal, including ordering, to the runtime subset. The verifier independently parses and compares the running server's subset to the committed snapshot, ignoring JSON object property order. This is the direct connection between server artifact and retained contract; it does not rely on the website's latest document.
- `opencode-2.1.4-connection-evidence.json` records actual probe outcomes and the environment. Credentials are absent; PID, port, and temporary path are replaced. The actual runtime PID matched the owned process. The verifier's controlled timeout fixture is a TCP listener, not an OpenCode response.

The full OpenAPI document and downloaded binaries are temporary verification inputs, not repository deliverables. Use [the reproducible verifier](../verify-connection.ps1) and [connection contract instructions](../opencode-connection-contract.md#reproduction-and-cleanup) to obtain them again. See the contract document for authentication annotations missing from OpenAPI and lifecycle statuses implemented outside the declared operation.

## Project/session contract (WI-005)

Retrieved on 2026-10-24 from the same hash-verified executable above. [The project/session snapshot](opencode-2.1.4-project-session.openapi.json) retains ten complete runtime path objects: location, filesystem list, project list, session list/create, session by ID, message list, experimental import (fixture only), models, default model and agents. Root OpenAPI metadata and the transitive closure of 97 referenced schemas are retained unchanged. Every schema reference resolves within the snapshot. [The verifier](../verify-project-session.ps1) compares later runtime slices to this snapshot using structural JSON equality.

The wider runtime slice differs from the frozen source used by WI-001: project/session archive fields, the message `idle` filter, compatibility import description/schema, and 19 referenced schemas (model/provider compatibility/settings/capabilities and assistant/native/compaction/error representations). The source commit is therefore not the project/session contract authority. The narrower WI-001 connection equality remains valid. No binary build commit is inferred. Use the retained runtime schemas for implementation.

[Project/session evidence](opencode-2.1.4-project-session-evidence.json) retains 31 checked runtime outcomes. Bodies are parsed JSON, owned temporary roots are replaced, nonempty cursors are replaced because they can embed paths, and models/agents are projected to availability fields. Provider settings/headers, authorization and credentials are omitted. Session IDs/timestamps are disposable fixture values. History was imported without provider execution; this is evidence of projected retrieval, not of task completion. See [the workflow contract](../opencode-project-session-contract.md) for commands, client decisions and unobserved cases.

## Task-workflow contract (WI-007)

Retrieved on 2026-10-24 from the same hash-verified executable. [The task-workflow snapshot](opencode-2.1.4-task-workflow.openapi.json) retains 25 complete runtime path objects covering model/agent selection, session metadata/active state, prompts/inbox, history, interrupt/wait, permissions/saved rules, forms, global events and the experimental session log. Root metadata and the transitive closure of 135 referenced schemas are unchanged. Every local schema reference resolves. [The verifier](../verify-task-workflow.ps1) structurally compares subsequent runtime slices against the retained snapshot; a second isolated run passed that comparison. The opaque event-encoding schema does not describe the native event envelope; the observed event bodies are retained separately.

[Task-workflow evidence](opencode-2.1.4-task-workflow-evidence.json) contains 110 named service checks and 91 native events from the real pinned server with the [deterministic loopback provider](../task-provider-fixture.mjs). It exercises completion, provider rejection, actual read/question tools, queued admission, interruption, permission replies/saved rules, form validation/cancellation, subscriber disconnect and authoritative REST reconciliation. Provider output is controlled fixture content, not real-model evidence. One acknowledgement is deliberately discarded by the simulated client; this is not a wire-level loss test. The experimental log returned a sync marker without replayable events in this run.

Bodies are parsed before sanitization, temporary roots/ports and nonempty history cursors are replaced, and model/agent lists omit settings and headers. All sessions/content originate in disposable fixtures. The retained evidence contains no authorization, real provider credentials or private project content. See [the contract](../opencode-task-workflow-contract.md) for exact commands, UI state rules, reproduction prerequisites and unverified boundaries. Node.js and the verifier-only [C# SSE consumer](../task-events-fixture.cs) are additional local prerequisites; neither is a production App dependency.
